# ADR-003: Shell editorial Starlight com CSS/overrides do Starlight Obsidian Theme (sem Graph View)

**Status:** Accepted
**Date:** 2026-09-23
**Deciders:** usuário (decisão "(d) Atual, sem grafo")

## Context
Correção estrutural do usuário: Astro + Starlight + Starlight Obsidian Theme + GitHub Markdown CSS + tokens mínimos. O spike 4a (`07-execucao/04a-spike-shell.md`) mostrou que o plugin do tema 0.4.1 falha em Astro 7 por causa de `starlight-site-graph` 0.5.0 (zod 4).

## Decision
Usar Starlight 0.42 com os arquivos CSS do tema (`layers`, `theme`, `centered-reading`, `common`) via `customCss` e os overrides `Sidebar`, `PageFrame`, `Pagination`, `ThemeSelect`, **referenciados do pacote npm** (sem cópia). `PageSidebar` fica o padrão do Starlight (TOC). Sem Graph View e backlinks.

## Options Considered
### (a) Versões travadas (Astro 5.16 / Starlight 0.36 / engine 0.10.1)
Pros: tema completo com grafo. Cons: 2 majors atrás, sem atualizações.
### (b) Fork do `starlight-site-graph`
Pros: grafo na stack atual. Cons: código próprio a manter.
### (d) Atual sem grafo (escolhida)
| Dimension | Assessment |
|---|---|
| Complexity | Low (só config) |
| Cost | Zero |
| Maintenance | Stack atual, `npm update` |

## Trade-off Analysis
Atualizabilidade e zero código próprio superam o Graph View, que é opcional para leitura.

## Consequences
- Mais fácil: acompanhar Astro/Starlight.
- Mais difícil: overrides do tema podem quebrar em futuras versões do Starlight (coberto por `check`/e2e).
- Revisitar: reativar o plugin completo quando o tema/site-graph suportar Astro 7.
