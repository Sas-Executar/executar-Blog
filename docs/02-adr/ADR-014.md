# ADR-014: EXECUTAR Studio (editor, preview, validação, publicação e MCP)

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** usuário (ADR "Editorial Studio Full Stack", entregue como "ADR-008"; renumerado porque 008 já existia)

## Context
Publicar exigia saber Git e Markdown do Obsidian. O usuário quer escrever, ver exatamente como fica, validar e publicar sem sair de uma tela, e quer que agentes façam o mesmo por MCP. Tudo sem expor credenciais no navegador.

## Decision
- **App separado** `apps/studio`: Astro estático + Worker `executar-studio` (`/api/*` e `/mcp` com `run_worker_first`).
- **Preview idêntico ao blog:** `packages/editorial-renderer` roda o **mesmo** parser no navegador (Sätteri em WebAssembly, `@bruits/satteri-wasm32-wasi`, baixado por `apps/studio/scripts/satteri-wasm.mjs` porque o npm recusa pacotes `cpu: wasm32`). O WebAssembly com threads exige isolamento de origem, então `public/_headers` define COOP `same-origin` e COEP `credentialless`.
- **Validação** com o mesmo `content-schema` no navegador (tempo real) e de novo no Worker antes de gravar.
- **Publish API** `POST /api/publicar {modo, caminho, markdown, assets[]}` com commits atômicos pela Git Data API (blobs → tree → commit):
  - `draft` → ramo `rascunho/<slug>`, fora do site;
  - `preview` → ramo `preview/<slug>`, com prévia do Workers Builds;
  - `pr` → ramo `artigo/<slug>` e pull request;
  - `publish` → fast-forward da `main`, que falha se a `main` mudou (sem force).
- **Limites:** caminhos só dentro de `vault/`, sem `..` nem ocultos; Markdown ≤ 1 MB, imagem ≤ 5 MB, envio ≤ 10 MB; limite de taxa de 30 escritas por minuto por pessoa.
- **Credenciais:** GitHub App (`GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_INSTALLATION_ID`; JWT RS256 via WebCrypto → token de instalação de 1h) ou `GITHUB_TOKEN` fine-grained (Contents e Pull requests: read/write, só este repositório). Ficam **só** em secrets do Worker.
- **Acesso:** Cloudflare Access na frente do Worker, e o Worker **também** valida o JWT (RS256, `aud`, `iss`, `exp`) contra as chaves do time (`ACCESS_TEAM`, `ACCESS_AUD`). Sem configuração, tudo é negado (fail closed).
- **MCP:** `/mcp` (Streamable HTTP, JSON-RPC 2.0, protocolo `2025-06-18`) com as ferramentas `listar_artigos`, `ler_artigo`, `validar_artigo`, `pre_visualizar` e `publicar`. Usa a mesma Publish API e o mesmo Access (service token para agentes).
- **Saídas:** Web (blog), PDF (impressão do navegador no Studio; `npm run export:pdf` com Playwright) e EPUB 3 (`gerarEpub` sem dependências, no Studio e em `npm run export:epub`).

## Pendências que só o usuário resolve
1. Criar o GitHub App (ou o token fine-grained) e instalar no repositório. Passo a passo em `docs/06-docs/GUIA-ARTIGO-MARKDOWN.md`, seção 6.
2. Ativar o Cloudflare Zero Trust (nome do time) e informar os e-mails autorizados.

## Consequences
- Publicar passa a ser: escrever → ver → validar → um botão. O Git continua sendo a fonte da verdade, e cada publicação é um commit auditável.
- O Studio não funciona sem Access e sem credencial do GitHub. Por segurança, esse é o comportamento esperado.
