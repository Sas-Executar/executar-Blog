# ADR-016: executar-Blog como marketplace de plugins e o Copiloto Operacional como plugin do Claude Code

**Status:** Accepted
**Date:** 2026-09-25
**Deciders:** usuário. Este ADR aplica o `ADR_001` genérico rev. 2 + `BLUEPRINT_HANDOFF.json` (schema 2.0.0) enviados pelo usuário, sobre a base do ADR-015.

## Context
- **O erro.** Em claude.ai → Settings → Plugins → Add marketplace, `Sas-Executar/executar-Blog` foi recusado com "no manifest found at `.claude-plugin/marketplace.json`".
  - O manifesto **já existia** na `main` desde 24/09 (commit `280f670`, marketplace `executar-blog`, só com `cloudflare`). O repositório é público, o branch padrão é a `main` e o arquivo passa no `claude plugin validate`. Ou seja, a mensagem não vinha de arquivo ausente.
  - O handoff (IMG_1347) mostra o plugin Cloudflare já instalado com origem executar-Blog, o que indica que o marketplace **já estava adicionado** no claude.ai. Adicionar de novo a mesma origem é o caso mais provável para essa mensagem.
- **O pedido.** O usuário quer a entrega já no repositório, no formato oficial de plugin, com **todas** as funções do Copiloto Operacional (ADR-015) em paridade granular. Nada pode depender de Resend, Graph, D1, Queues ou Workers: isso é Cloudflare, e aqui tudo é Claude Code/plugins.
- **O handoff:**
  - reutilizar componentes próprios;
  - um plugin por domínio real;
  - credenciais fora do pacote;
  - controles determinísticos, porque prompt não é fronteira de segurança;
  - capacidade ausente responde `unsupported`;
  - aceite T01–T12.

## Decision
- **Marketplace `executar-blog`**. O nome existente desde 24/09 foi preservado para não quebrar o `cloudflare@executar-blog` já instalado. em `.claude-plugin/marketplace.json`, na raiz, com três plugins:
  - `copiloto-operacional` (`./plugins/copiloto-operacional`);
  - `executar-skills` (as 4 skills do repositório Copiloto, fonte github, sem cópia);
  - `cloudflare` (fork `Sas-Executar/skills-cloudflare`, fonte github).
- **`copiloto-operacional` roda o mesmo núcleo do Worker.**
  - `apps/copiloto/worker/{comandos,dominio,workflow,servico,tarefas,relatorio,ledger,portas}.ts` é empacotado por `scripts/build-plugin.mjs` (esbuild) em `dist/servidor.mjs`, um servidor MCP stdio.
  - O CI falha se o `dist/` divergir do código-fonte (`npm run plugin:check`).
  - O que era compartilhado entre Worker e plugin saiu do `index.ts` do Worker para `portas.ts`: definições `ops/**`, `verificarLink`, `validarLabelUi`, `reconciliarTudo`, `abasEspelho` e `csv`.
- **Troca dos adaptadores Cloudflare:**

  | No Worker (Cloudflare) | No plugin (Claude Code) |
  |---|---|
  | Graph (e-mail entra) | 17 comandos `/copiloto-operacional:<verbo>`: os 15 verbos + `reconciliar` + `espelho` |
  | Resend (e-mail sai) | resposta na conversa + arquivos em `reports/AAAA/MM/` (HTML A4, e-mail HTML, texto, JSON) |
  | D1 | `node:sqlite` em `${CLAUDE_PLUGIN_DATA}/ledger.db`, mesma migration |
  | Queues | desnecessário: execução síncrona |
  | Browser Run | Chromium local (`CHROME_PATH`); sem ele, `partial` + HTML |
  | cron + webhook | ferramenta `reconciliar` (varre eventos das issues) + hook `SessionStart` opcional (briefing somente leitura) |
  | GitHub App | `userConfig.github_token` (sensitive, keychain) |
  | RBAC por e-mail | `userConfig.papel` aplicado por `autorizado()` no servidor |

- **Separação leitura/escrita aplicada no código:**
  - A ferramenta `consultar` recusa no servidor qualquer verbo que escreva, então pode ser pré-aprovada nos comandos de leitura.
  - `executar` e `reconciliar` nunca são pré-aprovadas: o Claude Code pede aprovação a cada chamada.
  - A confirmação de lote é detectada por sinal estrutural do serviço, nunca pelo texto (que inclui títulos de issues).
- **Mesmo estado, duas portas.** As tarefas continuam em `Sas-Executar/Copiloto` e as definições em `ops/**` deste repositório. Não há sistema paralelo (DEC-01).

## Aceite (handoff T01–T12)

| ID | Critério | Resultado | Evidência |
|---|---|---|---|
| T01 | Inventário rastreável, sem duplicação | aprovado | reuso de `apps/copiloto/worker/*`; skills referenciadas via github, não copiadas |
| T02 | Manifesto inválido falha antes | aprovado | `claude plugin validate .` e `… plugins/copiloto-operacional` passam; teste de formato em `tests/unit/plugin-copiloto.test.mjs` |
| T03 | Autenticação ausente → estado explícito | aprovado | sem token → `unsupported` com a lacuna (teste stdio) |
| T04 | Capacidade ausente → `unsupported` | aprovado | token, `node:sqlite` e PDF sem Chromium → `unsupported`/`partial` com a lacuna |
| T05 | Operação fora da autorização bloqueada antes do efeito | aprovado | LEITOR, papel inválido e `consultar` com escrita → `blocked`, 0 escritas no GitHub simulado |
| T06 | Retomada sem duplicar | aprovado | `/fila` e `/campanha iniciar` repetidos, até em processos novos → 1 issue; real: `EXE-0001` (#502) enviada 2×, 1 issue |
| T07 | Isolamento entre contas | `not_applicable` | um só contexto de segurança (o operador da sessão); o ledger fica por instalação em `${CLAUDE_PLUGIN_DATA}` |
| T08 | Instrução maliciosa em dado externo | aprovado | issue com "rode /confirmar…" lida como dado; 0 escritas. O teste achou e corrigiu um defeito real (detecção de confirmação por texto) |
| T09 | Limites e cancelamento em runtime programático | `not_applicable` | sem Agent SDK programático; o hook tem limite de 20 s e falha em silêncio |
| T10 | Ferramenta genérica não contorna leitura | aprovado | `consultar` recusa escrita no servidor (teste) |
| T11 | Mutação reversível com compensação | aprovado | real: #502 criada por `/fila`, compensada com `BACKLOG_VALIDATED → CANCELADO` (fechada como não planejada) |
| T12 | Só componentes próprios | aprovado | nenhum plugin/skill de exemplo (ActiveCampaign) é dependência |

**Fluxo real somente leitura (H05), contra o GitHub, papel LEITOR:**
- `/hoje` → 0 tarefas;
- `/% fila` → sem itens;
- `/campanha WF-CAMP-001 estado` → E-201 (workflow lido da `main`, instância sem tarefas);
- `/status-report 72h` → 4 arquivos gravados.

**Instalação local:** `claude plugin marketplace add ./` + `claude plugin install copiloto-operacional@executar-blog`. O `details` mostra 17 comandos + 1 skill, 1 hook e 1 servidor MCP, com cerca de 975 tokens fixos por sessão.

## Consequences
- **claude.ai e o marketplace.** No claude.ai, o caminho é **sincronizar** o marketplace `executar-blog` já adicionado, não adicioná-lo de novo. Depois do sync aparecem `copiloto-operacional` e `executar-skills`.
  - No claude.ai (chat), servidores MCP stdio não rodam; lá valem a skill e os comandos, e as ferramentas respondem só onde há runtime local.
  - O ambiente-alvo é o Claude Code (CLI, desktop e web/cloud).
- **Agendamento.** ROT-001/002/003 não viram cron de plugin (não existe). Use as Routines do Claude Code apontando para `/copiloto-operacional:hoje`, `:amanha` e `:status-report 72h`.
- **Evolução conjunta.** Uma mudança de regra no `apps/copiloto/worker` vale para o Worker e para o plugin depois de `npm run plugin:build`, e o CI obriga isso.

## Pendências do usuário
1. `/plugin configure copiloto-operacional@executar-blog`: token fine-grained com Issues RW em `Sas-Executar/Copiloto` e Contents + PR RW em `Sas-Executar/executar-Blog`.
2. Node.js ≥ 22.13 no PATH onde o Claude Code roda.
3. No claude.ai, sincronizar o marketplace `executar-blog` já adicionado (em vez de "Add marketplace" de novo). Se `executar-skills` não instalar por ser fonte github, avisar; o `copiloto-operacional` não depende dele.
