# ADR-006: Apple Human Interface Guidelines aplicadas transversalmente

**Status:** Accepted
**Date:** 2026-09-23
**Deciders:** usuário ("Apple HIG vence")

## Context
O Blueprint pedia HIG + Fluent. O usuário decidiu que o HIG vence qualquer conflito visual. Fonte: https://developer.apple.com/design/human-interface-guidelines (Accessibility, Typography, Color, Dark Mode, Layout, Motion, Writing, Charts — lidos em 2026-09-23).

## Decision
Regras mensuráveis do HIG viram tokens e testes automatizados. Nenhum design system novo: os tokens só sobrescrevem valores do tema/Starlight.

| Regra HIG (citação resumida) | Token / implementação | Teste |
|---|---|---|
| Texto padrão iOS 17 pt, mínimo 11 pt | `--font-size-body: 1.0625rem` (17px); nada abaixo de 11px | e2e: computed font-size do corpo ≥ 17px; nenhum texto visível < 11px |
| "Support larger text sizes… enlarge text by at least 200 percent" | unidades `rem`; layout empilha | e2e: zoom 200% sem overflow horizontal |
| Contraste mínimo 4,5:1 (WCAG AA) em light e dark | pares de cor dos tokens | `check-contrast.mjs` + axe |
| "Increase Contrast" | `@media (prefers-contrast: more)` | e2e emula |
| Controles 44×44 pt (iOS), espaçamento ~12pt | `--hit-target: 44px` em links de navegação, botões, busca, toggle | e2e mede bounding boxes |
| "Reduce Motion": reduzir animações automáticas | `@media (prefers-reduced-motion: reduce)` | e2e emula |
| Dark Mode testado em ambos | tokens light/dark | screenshots e axe nos dois |
| Layout adaptável, safe areas | `env(safe-area-inset-*)` | e2e 375/768/1280 |
| Fonte do sistema (SF) | `--font-sans: -apple-system, BlinkMacSystemFont, system-ui, "Segoe UI", Roboto, sans-serif` — sem embutir arquivos SF | — |
| Capitalização consistente | sentence case em rótulos de UI (regra no CLAUDE.md) | revisão |
| Gráficos acessíveis: título, tipo, eixos, resumo | `<Grafico>` exige `titulo` e `resumo`; ECharts `aria.enabled` | teste unitário |
| Não fazer autoplay de mídia | regra no CLAUDE.md | revisão |

Fluent (R-12): deixa de ser linguagem visual; os princípios comuns de acessibilidade ficam cobertos pelos mesmos testes.

## Options Considered
- HIG como checklist mínimo (plano v2) — rejeitado pelo usuário.
- HIG + Fluent visuais — geraria um terceiro design system.
- **HIG transversal via tokens + testes (escolhida).**

## Consequences
- Mais fácil: acessibilidade verificada por máquina a cada PR.
- Mais difícil: tokens podem divergir do visual original do tema (aceito: HIG vence).
