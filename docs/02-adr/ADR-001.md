# ADR-001 — Obsidian UI como dependência upstream do Blog

**Status:** Superseded por ADR-002 e ADR-003 (2026-09-23)

> Estágio 0 confirmou que os comandos existem, mas o Arrow Sandbox é um protótipo de UI de plugin, `pull-css` depende do Obsidian instalado e o `app.css` não pode ser distribuído. Ver `07-execucao/00-verificacao.md`.

**Origem:** `Blueprint.md` do usuário
**Estratégia:** minimal code, max arrow

## Objetivo

Construir o novo repositório com UI Obsidian/Minimal sem criar ou manter
design system próprio. A decisão privilegia automação por Claude Code,
pouco código proprietário e dependências upstream atualizáveis.

## Decisão

Adotar **Obsidian Arrow Sandbox** como scaffolding e infraestrutura de
desenvolvimento, combinado com **Obsidian Minimal** como Git submodule.

O Arrow Sandbox, segundo o Blueprint, fornece: scaffolder, `CLAUDE.md`,
skills para agentes, Vite, checks e `pull-css`. O `app.css` do Obsidian
permanece fora do Git. O Minimal é MIT e fornece CSS/build reutilizável.

> ⚠️ Estas capacidades do Arrow Sandbox constam no Blueprint mas **não foram
> verificadas**. Ver `HANDOFF.md` → "O que não está verificado".

### Estrutura alvo

```
blog/
├── src/
├── public/
│   └── app.css              # gerado por pull-css; NÃO versionado
├── vendor/
│   └── obsidian-ui/         # git submodule → obsidian-minimal
├── CLAUDE.md
├── package.json
└── .gitmodules
```

### Bootstrap (do Blueprint — validar antes de executar)

```bash
npm create obsidian-arrow@latest .
npm install

git submodule add \
  https://github.com/kepano/obsidian-minimal.git \
  vendor/obsidian-ui

git submodule update --init --recursive

npm run pull-css
```

Skills do Arrow para Claude Code:

```bash
npx skills add kylebrodeur/obsidian-arrow-sandbox \
  --all --yes --agent claude-code
```

## Source of Truth (precedência)

```
Obsidian app.css
      ↓
Obsidian Minimal
      ↓
componentes Arrow
      ↓
Blog
```

### Não criar

- pacote local de design tokens;
- cópia de CSS upstream;
- abstração própria equivalente ao Obsidian;
- componentes que já possam ser representados pelas classes/primitivas
  existentes.

### Regras

- `app.css` obtido por `npm run pull-css` e **ignorado pelo Git**.
- `vendor/obsidian-ui` permanece **submodule**, nunca copiado para `src`.
- Alterações no upstream **não** são feitas dentro de `vendor/`.

## Regra para Claude Code

Antes de implementar UI, seguir esta prioridade:

1. reutilizar classes/tokens do Obsidian;
2. reutilizar Minimal;
3. reutilizar primitives/patterns do Arrow Sandbox;
4. escrever CSS próprio somente quando 1–3 forem insuficientes.

## Atualização

```bash
npx create-obsidian-arrow refresh
git submodule update --remote vendor/obsidian-ui
npm run pull-css
npm run check
npm run build
```

## Consequências

**Positivas:** elimina manutenção de design system próprio, facilita
atualizações upstream, fornece ao Claude Code documentação e skills
específicas para mudanças com baixo volume de código.

**Restrição:** `app.css` pertence ao Obsidian e não será redistribuído no
repositório. O Minimal é a parte open source versionada/reprodutível da
camada visual.

## Critério arquitetural

Qualquer nova implementação que replique manualmente comportamento ou
estilo já existente no Obsidian, Minimal ou Arrow Sandbox é **duplicação**
e deve ser evitada.
