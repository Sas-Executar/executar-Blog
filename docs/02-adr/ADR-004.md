# ADR-004: Conteúdo via `starlight-obsidian` a partir de um vault limpo

**Status:** Accepted
**Date:** 2026-09-23
**Deciders:** usuário

## Context
Os 21 artigos vêm de um vault Obsidian com IDs (FRC-xx, ARTICLE-MASTER…), briefing de infográfico (seção 13), link interno ao Knowledge Pack e arquivos internos. Usuário pediu limpeza editorial e quer experiência próxima do Obsidian.

## Decision
1. `scripts/import-content.mjs` (execução única, testada) gera `vault/` limpo, com `.obsidian/app.json`, nomes sem ID, frontmatter `title`/`description`, relacionados como wikilinks.
2. `starlight-obsidian` publica `vault/` em `src/content/docs/artigos/`.
3. Mermaid: o engine usa `rehype-mermaid` (Chromium). As páginas geradas são **commitadas** e o build Cloudflare roda com `skipGeneration` (variável `SKIP_OBSIDIAN=1`), porque o ambiente do Workers Builds não garante navegador. O CI (com Chromium) regenera e falha se houver diff.
4. `guard` impede IDs internos em `vault/`, `src/` e `dist/`.

## Options Considered
| Opção | Pros | Cons |
|---|---|---|
| Engine + páginas geradas commitadas (escolhida) | Mermaid real, build Cloudflare simples | Conteúdo gerado no Git (checado por CI) |
| Engine gerando no build Cloudflare | Nada gerado no Git | Depende de Chromium no Workers Builds (não confirmado) |
| Converter Mermaid em listas | Sem navegador | Perde diagramas |

## Consequences
- Usuário edita no Obsidian → `npm run content:sync` → PR.
- Revisitar se o Workers Builds confirmar Chromium disponível.
